## 1. Sumário executivo

**Objetivo.** Todo usuário do Trader Panel passa a fazer login no Seraph via Privy (email, SMS ou wallet SIWE/MetaMask) dentro do console `https://seraph.kondux.io`. Ao clicar "Authorize", o Omni-OS recebe um access JWT OAuth 2.1 (audience `https://seraph.kondux.io/api`, scopes `api-keys:write wallet:execute`), chama `POST /api/desktop/api-keys` no control-plane e recebe uma **API key `mcfw_` própria deste dispositivo**, guardada cifrada (DPAPI) e usada como `Authorization: Bearer mcfw_…` em `POST https://seraph.kondux.io/mcp`. O OAuth é **apenas** o passo de login/identidade; a credencial de trabalho é a API key. A conta Privy é também **a conta que opera**: cada usuário recebe uma **Carteira Seraph** (Privy embedded wallet criada no login), autoriza uma vez um **session signer** do Seraph (limitado por uma política global — Apêndice F) e, a partir daí, o trader executa trades reais chamando a nova ferramenta MCP **`guardian_execute`**, que só assina o payload **exato** que passou pelo gate `guardian_pretrade_check`. MetaMask e outras carteiras externas servem só para **login e depósito**. A antiga carteira local (chave privada importada no desktop) é **removida** — breaking change aceito (sem usuários reais).

**Resultado para o usuário final.** Primeiro uso: overlay "Connect to Seraph" (o painel inteiro fica bloqueado até o login) → "Sign in with Seraph — we'll create your API key automatically" → browser → Privy (email/SMS/wallet) → consent 1 "Omni-OS Trader wants to create a Seraph API key for this device" → consent 2 "Autorizar o Seraph a executar trades com sua Carteira Seraph (limites: até 0,02 ETH por transação, 0,2 ETH e 20 transações por dia, só swaps Uniswap nas 7 redes; revogável a qualquer momento)" → aba "You can close this tab" → status "Creating your Seraph API key…" → header `Seraph: key mcfw_3fa9c1e (signed in)` e bloco **Carteira Seraph** com endereço, saldos, status do signer, "Depositar", "Retirar ↗" e "Gerenciar no console". Quem entrou por MetaMask vê **também** a carteira externa (só leitura) com a frase "Seus trades usam a Carteira Seraph (…), não sua carteira externa (…). Deposite fundos na Carteira Seraph para operar." — só a Carteira Seraph opera; retiradas para a carteira externa são feitas pelo próprio usuário no console (D31/D32). Usuário novo é provisionado automaticamente no `authorize` (org free/active + user + membership + subscription + API key default + sandbox + guardrails) e recebe a key do dispositivo. A key sobrevive a reinícios indefinidamente. Se a key for revogada (401), o app re-emite silenciosamente com o refresh token; só se isso falhar pede novo login. Não existe "Sign out": o único botão é **"Desconectar este dispositivo"** (apaga key e tokens locais e revoga a key no servidor, best effort). Trades reais só acontecem quando o signer foi autorizado; sem ele o trader fica em paper. Nenhuma key, seed ou chave privada é digitada, copiada, vista ou armazenada no desktop.

### 4.4 Modelo de armazenamento e precedência

- Desktop: bloco `settings.json["seraph_auth"]` (Apêndice B), arquivo inteiro cifrado por DPAPI quando disponível; senão plaintext com warning + `secure_storage=False` na UI. **Nenhum dado de carteira no desktop** (nem endereço): a UI consulta `guardian_wallet_status` (cache 30 s em memória).
- Credencial primária = `api_key` (`mcfw_…`) + `api_key_source`. Tokens OAuth no mesmo bloco só para re-mint e "Desconectar este dispositivo". `client_id`, `device_id`, endpoints e metadata sobrevivem ao disconnect; `api_key*`, tokens, `subject`, `org_id`, `scope` são zerados.
- Precedência `McpClient._resolve_credential()`: `api_key_explicit` → `key_provider()` (`api_key_oauth`|`api_key_manual`) → legado Guardian (`api_key_legacy`) → `api_keys.json` (`api_key_legacy`, só se não migrada) → `none`.
- Backend: `user.privy_wallet_id/address/signer_granted_at/signer_policy_id`; `wallet_gate(request_id PK, org_id, user_id, kind, chain_id, "to", value_wei numeric, call_data text, "from", decision, reason, decided_at, expires_at, consumed_at, created_at)`; `wallet_execution(request_id PK FK, user_id, wallet_address, chain_id, tx_hash, status allow|failed, error_code, gas_limit, max_fee_per_gas, created_at)`; `wallet_daily_spend(wallet_address, utc_day, spent_wei numeric, tx_count int, PK(wallet_address, utc_day))`.

**Dívida técnica (registrar em `docs\plans\...-execution-log.md` e no PRD):**
1. **DPoP** no `/token` não implementado no desktop (Q20) — se o auth-api tornar obrigatório, o login quebra; plano: `crypto.subtle` ECDSA P-256 + `jwk` thumbprint.
2. **Policies por usuário** (limites individuais, allowlist de tokens) — hoje uma policy global; exige key admin online ou fluxo de aprovação.
3. **Cap diário stateful no Privy** — só documentado para `eth_signTransaction`/`eth_signUserOperation`; hoje o cap diário é só do backend.
4. **Key órfã em casos de borda**: `DELETE` best effort pode falhar offline → key revogada só no próximo login (rotação) ou no console.
5. **`userId` para tenants OAuth** (JWT `aud /mcp`) não resolvido — clientes OAuth (Claude) não executam; se necessário, lookup `sub → user` no `validate-org`.
6. **Saldos de tokens ERC-20** na Carteira Seraph (só nativo hoje) e QR gráfico no desktop/console.
7. **Aprovação humana por trade** (key quorum ≥ 2) — hoje o signer do Seraph é único.
